## 三、Introduction 初稿

> **采用的引言变体**：application-first（应用先行）。
> 理由：目标读者是能源与清洁生产领域，从具体的能耗痛点切入比从抽象任务定义切入更贴近该刊读者的阅读习惯；且本文的动机本身就是一个具体的工程困境。

### 第 1 段 · 确立领域重要性

人工智能模型的训练与推理需求在近年持续快速增长，使算力基础设施成为电力消费增长最快的部门之一 `[C1]`。在双碳目标约束下，算力中心的用能与碳排放已从单纯的运营成本问题，转变为需要同时接受能耗强度考核、碳排放核算与绿电消纳责任约束的多重管理对象 `[C2]`。与传统高耗能行业不同，算力中心的负荷具有高功率密度、强时变性和异构硬件并存的特征：同一园区内往往同时部署多代加速卡，承载训练、微调与推理等性质迥异的计算任务，其功率曲线在小时尺度上即可出现数倍波动。这些特征使得沿用传统工业能源管理中「按月盘点总量」的做法难以支撑精细化的减碳决策。

### 第 2 段 · 指出现有实践的瓶颈

当前算力中心的能碳管理实践普遍停留在**总量台账层面**：可以报出全年用电量、平均 PUE 与折算碳排放，却难以回答与减碳决策直接相关的具体问题。这一局限集中体现在三个方面。其一，**缺乏归因能力**——能够给出某月能耗偏高的结论，却无法指出是哪类计算任务在哪种机型上、于哪个时段造成了偏高，也无法识别装机但未承载任务的设备所产生的待机浪费。其二，**缺乏对可再生能源真实贡献的评估**——园区配置的风电、光伏与储能通常以装机容量或年发电量计入减碳成效，而实际消纳率、时段错配程度，尤其是储能因往返效率损失和充放电时段碳强度差异所导致的净效果，很少被单独测算。其三，**缺乏统一的功能单位**——不同园区、不同时期的碳排放数据以绝对量呈现，既无法横向对标，也难以支撑「同样的产出，如何排得更少」这一核心问询。

### 第 3 段 · 前人工作与未解决的缺口

已有研究从若干侧面推进了上述问题。在核算层面，数据中心碳排放的核算方法与 PUE 等能效指标体系已相对成熟 `[C3]`，面向机器学习任务的碳排放估算工具亦已出现，可按运行时长、硬件型号与区域电网因子给出单次训练的碳足迹估计 `[C4]`。在优化层面，大量工作关注负载时空调度、余热回收与可再生能源协同，以在服务质量约束下降低成本与碳排 `[C5]`。在设备层面，信息通信技术设备的隐含碳与生命周期评价研究表明，硬件制造阶段的排放在总量中占比不可忽略 `[C6]`。

然而，面向算力园区的**分析型**方法仍存在四点未解决的缺口。**第一**，现有核算多以时段或任务为口径，尚缺少一个可跨园区、跨时期对标的**单位产出**功能单位；而在工业碳核算中，单位产品碳足迹早已是通行做法 `[C7]`。**第二**，异构硬件带来的能效差异通常被平均化处理，「同一类任务在不同机型上能效相差多少」这一差异性问题缺少系统的分析方法。**第三**，储能的减碳作用在多数研究中被**默认为正**，其净效果对充电电源构成与时段碳强度差的敏感性未被显式检验。**第四**，硬件隐含碳普遍按日历时长线性摊销，这一处理隐含了「使用频率不影响老化速度」的假设，因而无法回答使用强度如何影响设备的生命周期成本与回收再利用价值。

### 第 4 段 · 本文的做法

针对上述缺口，本文提出一套面向算力园区的能碳分析方法与 Agent 框架。方法层面，本文将算力园区类比为工业园区——电力为原料，服务器机型为生产线，Token 为产品——从而把工业碳核算中成熟的单位产品碳足迹方法迁移至算力场景，以**每百万 Token 碳足迹**（gCO₂e/MTok）作为顶层功能单位。在此基础上，本文以能碳数据的三项固有特性组织分析：**差异性**用于刻画任务类型与服务器机型交叉条件下的能效离散程度；**时序性**用于识别负荷、可再生出力、电价与碳强度之间的周期结构与相位错配；**不稳定性**用于表征波动幅度、突变与尖峰。框架层面，本文构建一个大模型驱动的 Agent，通过调用一组本地只读工具完成取数与测算，并将分析结果组织为对三个核心问题的回答；为控制数据外传风险，Agent 仅接收聚合统计量，原始明细数据不离开本地。

### 第 5 段 · 贡献与边界

本文的主要贡献如下：

1. 提出算力工业园区分析框架，确立**每百万 Token 碳足迹**为功能单位，并给出包含 Token 统计口径、碳算法、隐含碳处理方式与电耗边界在内的**口径标注体系**，使测算结果具备可比性；
2. 提出面向能碳数据的**三性分析方法**，将差异性、时序性与不稳定性的度量与算力场景的具体问题相对应；
3. 提出**空置率与空载能耗**测算方法，区分物理空置与逻辑空置，量化装机未使用所造成的待机浪费；
4. 提出**储能净减碳判据**，显式计入往返效率损失与充放电时段碳强度差，给出该值为负（即储能增碳）的条件；
5. 提出**基于等效运行小时的隐含碳摊销方法**，将使用强度纳入寿命折损，进而支持生命周期成本与梯次利用潜力的测算；
6. 设计**数据边界受限的 Agent 架构**，在利用大模型分析能力的同时保证原始明细数据不出本地。

需要明确的是本方法的适用边界。本文提出的是**测算、识别与归因**方法，不求解带服务质量约束的成本—碳联合优化问题，亦不直接实施算力调度或储能控制；平台仅给出可迁移负载的理论量，任务能否迁移由运行方判断。此外，本文的寿命折损模型是一个**工程简化模型**，用于提供机型间可横向比较的相对指标，不用于预测单台设备的失效时间。
