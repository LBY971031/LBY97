# 合成测试数据

**⚠️ 这里的每一个数字都是为了测试流水线编造的，不是任何真实设施的实测值，
绝不可出现在报告或论文里。**

## 用途

`hour_2026-08-30T15.json` 是一小时（2026-08-30 15:00–16:00 +08:00）的
园区数据，用来验证 Agent 流水线跑得通、三道闸拦得住。

| 内容 | 规模 |
|---|---|
| 服务器 | 4 台，3 种机型（8×H100 ×2、8×A100、4×L40S） |
| 算力任务 | 10 个，6 种模型 |
| 功率采样 | 240 条（4 台 × 60 分钟），其中 **15 条为 absent** |
| 电网 | 该小时的电源结构与排放因子 |

## 刻意埋进去的三个坑

1. **数据缺口**：srv-03 的 BMC 在 15:20–15:35 掉线，15 条功率采样标为
   `absent`。**全套数据完整的样本测不出三道闸**——不制造缺口，就看不到
   「无法计算」而不是「一个变小了的数」。
2. **跨小时任务**：T01 从 14:52 开始、T03 到 16:20 结束，用来验证半开
   区间重叠判据，而不是简单的时刻相等。
3. **同机并发**：srv-01 上 T01 与 T02 同时各占 4 卡，用来验证按 GPU
   份额逐分钟分摊，以及空载能耗不被摊给任务。

## 排放因子是占位值

`ef_gco2e_per_kwh: 280.0` 标着 `PLACEHOLDER - not a real published factor`。
真实因子必须来自带版本号的因子库，此处只为让链路跑通。

## 重新生成

```bash
python samples/seed_hour.py
```

功率不是随机生成的，而是由任务占用的 GPU 数推出来：
`power = idle_kw + (max_kw - idle_kw) × 忙碌卡数 / 总卡数`。
所以能耗和任务是内部自洽的，重跑结果完全一致。
