# 「机型 × 模型」Token 碳足迹矩阵的计算方法

> 编制日期：2026-09-07
> 目标产出：一张 `服务器机型 m × AI模型 k` 的矩阵，每格是 **gCO₂e/MTok**，作为 SubAgent 的输入
> 计算位置：**全部在 `core/`**，LLM 只读结果，不参与任何一步计算

---

## 零、两个必须先立的前提

### 前提一：最小计算单元是 (m, k, t)，不是 (m, k)

**不能直接算 (机型 × 模型) 这一格，必须先落到时段级。** 因为：

```
Σ_t ( E_t × EF_t )  ≠  ( Σ_t E_t ) × EF_平均
```

碳强度随时段变化，**先把整月能耗汇总再乘一个月均因子，结果是错的**。
只有当碳强度恒定、或负荷与碳强度完全不相关时两者才相等——**算力园区两个条件都不成立**
（负荷有日周期，碳强度也有日周期，两者高度相关）。

> 🔴 **这是本计算里最容易犯、也最难被发现的错误。** 数字照样算得出来，只是偏了。

### 前提二：分子分母必须同粒度对齐

```
gCO2e/MTok (m,k) = 碳排(m,k) ÷ ( Token数(m,k) ÷ 1e6 )
                     ↑              ↑
                这两个必须来自同一组 (m,k,t) 单元，缺一个就整格作废
```

若某时段有能耗但无 Token 计量（或反之），**该时段整体排除，并计入覆盖率**，
**不许一边用实测一边用估计**。

## 一、计算链路总览

```
                    ┌─────────────────────────────┐
                    │  ① 能耗归集 E_IT(m,k,t)      │  ← 三条路径按数据可得性降级
                    └──────────────┬──────────────┘
                                   ↓
                    ┌─────────────────────────────┐
                    │  ② 乘 PUE → E_total(m,k,t)   │
                    └──────────────┬──────────────┘
                    ┌──────────────┼──────────────┐
                    ↓              ↓              ↓
            ┌───────────┐  ┌───────────┐  ┌───────────┐
            │③运营碳排  │  │④硬件隐含碳│  │⑤训练碳摊销│
            │ 分时段算  │  │按等效工时 │  │Boundary C │
            └─────┬─────┘  └─────┬─────┘  └─────┬─────┘
                  └──────────────┼──────────────┘
                                 ↓
                    ┌─────────────────────────────┐
                    │  ⑥ 逐 (m,k,t) 汇总 → (m,k)   │
                    └──────────────┬──────────────┘
                                   ↓
                    ┌─────────────────────────────┐
                    │  ⑦ 除以 Token → gCO2e/MTok   │
                    │     + 七字段口径标注          │
                    └─────────────────────────────┘
```

## 二、① 能耗归集 `E_IT(m,k,t)`

三条路径，**按数据可得性自动降级**，并在结果里记录用了哪条。

### 路径 A · 逐卡计量（层级①细分，最优）

```
E_IT(m,k,t) = Σ_{卡 c ∈ 机型m，且 t 时段被模型k 占用}  ∫ P_c dt
```

**前提**：逐卡功率读数 + 「卡 → 任务 → 模型」的映射链完整。

> ⚠️ **仍有系统性误差**：`nvidia-smi` 在 A100/H100 上仅对约 25% 运行时段采样功率，
> MIG 分区级归属缺乏硬件支持。**不是"测了就准"**，见[分配问题分析](./分配问题的Skill可行性分析.md)。

### 路径 B · 整机功耗 + 卡时份额分摊（层级②物理分配）

```
第一步：先把空载能耗扣掉 ⭐
  E_可分摊(m,t) = E_整机实测(m,t) − 空载能耗(m,t)

第二步：按被占用卡时的份额分摊
  E_IT(m,k,t) = E_可分摊(m,t) × [ 卡时(m,k,t) ÷ Σ_k' 卡时(m,k',t) ]
```

> 🔴 **第一步不能省。** 空载能耗是**无主的浪费**，不属于任何模型。
> 直接按卡时份额摊整机功耗，会让正在跑的模型**背上不属于它的碳**——空置越多，背得越多。
> 这会得出「模型 k 在机型 m 上碳足迹很高」的错误结论，而真实原因是**那台机器一半的卡在空转**。

### 路径 C · 卡时 × 功率基线（最粗）

```
E_IT(m,k,t) ≈ 卡时(m,k,t) × 单卡平均功率基线(m,k)
```
基线取历史同组合的**中位数**（长尾分布，不用均值）。**结果须标注为估算值。**

### 回加约束（三条路径都要做）

```
Σ_k E_IT(m,k,t) + 空载能耗(m,t)  ≡  E_整机实测(m,t)

残差 residual(m,t) = 左边 − 右边
residual_pct = |residual| ÷ E_整机实测 × 100%

处理：按各 k 的相对比例回摊残差；residual_pct > 5% 时标注「分摊不可靠」
```

## 三、② 乘 PUE

```
E_total(m,k,t) = E_IT(m,k,t) × PUE(room(m), t)
```

**两个细节**：

1. **PUE 是机房级属性**，不是机型级。同一机型跨多个机房时，须按机房分别乘再合并
2. **PUE 随时段变**（制冷负荷随温度变化）。有实测分时 PUE 最好；只有月均值时**须标注**

---

## 四、③ 运营碳排（分时段算，不可先汇总）

```
【地域法】
  C_op_loc(m,k,t) = E_total(m,k,t) × EF_grid(t)

【市场法】
  E_green分摊(m,k,t) = E_园区绿电消纳(t) × [ E_total(m,k,t) ÷ E_园区总用电(t) ]
  C_op_mkt(m,k,t) = [ E_total(m,k,t) − E_green分摊(m,k,t) ] × EF_grid(t)
```

> **绿电分摊规则须显式声明**：上式按**用电量比例**分摊，是最常见做法，但不是唯一选择。
> 若你有绿电的专线供给关系（某绿电专供某机房），应按实际供给关系分摊，**不要按比例摊**。

## 五、④ 硬件隐含碳（按等效运行小时）

```
C_embodied_hw(m,k,t) = Σ_{设备 d ∈ 机型m}
      隐含碳(d)_gCO2e × [ 等效运行小时(d,k,t) ÷ 设计寿命等效小时(d) ]

其中：
  隐含碳(d)_gCO2e = server_specs.embodied_kgco2e × 1000     ← ⚠️ 单位换算，必须做
  等效运行小时(d,k,t) = 实际运行小时 × 强度系数 k_load
      k_load 按负载率分档：<30% → 0.6 ｜ 30~70% → 1.0 ｜ >70% → 1.3
  设计寿命等效小时(d) = lifetime_years × 365 × 24
```

> ⚠️ **单位陷阱**：`server_specs.embodied_kgco2e` 存的是 **kg**，而全流程用 **g**。
> 不做 ×1000 换算，结果会差三个数量级。

## 六、⑤ 训练碳摊销（Boundary C）—— 有个重复计算的陷阱

### 基本公式

```
每Token训练碳(k) = 训练总碳(k) ÷ 预期总服务Token量(k)
C_train(m,k)     = 每Token训练碳(k) × Tokens(m,k)
```

### 🔴 陷阱：模型在本园区训练时会重复计算

| 情形 | 训练碳在哪 | 正确做法 |
|---|---|---|
| **模型 k 在本园区训练** | **训练时段的能耗已被记入 `energy_records`，已算进运营碳** | ❌ 不能再加一次摊销<br>✅ 应做**跨期分摊**：把训练期的碳从训练期**挪到**服务期，总量不变 |
| **模型 k 是外部模型**（第三方开源/商用） | 训练碳发生在你的边界外，属上游排放 | ✅ Boundary C 下**新增**这笔摊销 |

> **不区分这两种情形，自训模型的碳会被算两遍。**
> 数据模型上需要一个 `model_trained_internally` 标记来区分。

### ⭐ 一个重要性质：训练碳与机型无关

训练碳是**模型 k 的属性**——模型在哪训练的，和它现在跑在哪个机型上无关。
所以它对同一模型 k 的**所有机型格子贡献相同的每 Token 值**。

**这直接影响矩阵怎么用**：

| 用途 | 该用哪个边界 | 为什么 |
|---|---|---|
| **机型间对比**（哪个机型更省） | **Boundary B** | 训练碳是各行的常数项，加上它只会稀释机型差异，不改变排序 |
| **对外交代**（这个服务排多少碳） | **Boundary C** | 完整边界，含上游 |

> 所以矩阵**应该出两版**：B 版用于内部优化决策，C 版用于对外报告。

## 七、⑥⑦ 汇总与最终指标

```
【逐 (m,k) 汇总 —— 注意：先分时段算碳，再对 t 求和】
  C_total(m,k) = Σ_t [ C_op(m,k,t) + C_embodied_hw(m,k,t) ] + C_train(m,k)
  Tokens(m,k)  = Σ_t Tokens(m,k,t)

【最终指标】
  gCO2e/MTok (m,k) = C_total(m,k) ÷ ( Tokens(m,k) ÷ 1,000,000 )
```

**同时应产出的配套指标**（同一矩阵形状，便于交叉分析）：

| 指标 | 公式 | 用途 |
|---|---|---|
| 每百万 Token 电耗 | `E_total(m,k) ÷ (Tokens ÷ 1e6)` | 去掉因子影响，看纯能效 |
| 能效 | `Tokens(m,k) ÷ E_IT(m,k)` | 机型对比（**用 IT 电耗，不含 PUE**） |
| 每百万 Token 成本 | `电费(m,k) ÷ (Tokens ÷ 1e6)` | 与碳并排看 |
| 运营/隐含/训练 三段占比 | 各段 ÷ C_total | 看碳排结构 |

## 八、口径标注（七字段，缺一不可）

每格结果必须携带：

| 字段 | 取值 | 为什么必须 |
|---|---|---|
| `token_scope` | in+out / out_only | 口径不同数值差近一倍 |
| `method` | location / market | **两版都要出** |
| `include_embodied` | 是 / 否 | 含不含硬件隐含碳 |
| `embodied_method` | equiv_hours / calendar | 摊销方式 |
| `energy_boundary` | it_only / with_pue | 含不含 PUE |
| **`allocation_method`** ⭐ | A逐卡 / B卡时分摊 / C基线估算 | **不同路径精度差很远** |
| **`boundary_level`** ⭐ | B / C | **B 用于对比，C 用于对外** |
| `factor_version` | 如 v1.2 | 因子版本 |
| `expected_service_tokens` | 数值 + 假设说明 | 仅 Boundary C 需要 |

**展示格式示例**：
```
42.3 gCO₂e/MTok
（地域法｜输入+输出｜含PUE｜含隐含碳按等效运行小时｜路径B卡时分摊｜Boundary B｜因子v1.2｜2026年7月）
```

## 九、哪些格子算不出来（数据契约）

按[数据存在性契约](../能碳.md#1610-数据存在性契约硬性-v51-新增)，**算不出就标 `absent`，不估不猜**。

| 缺什么 | 后果 |
|---|---|
| 该 (m,k) 组合的 Token 计量 | **整格 `absent`** —— 分母没有 |
| 该机型的整机功耗与逐卡功率都没有 | **整格 `absent`** |
| 卡时映射（不知道哪些卡跑了模型 k） | **整格 `absent`** —— 路径 B、C 都做不了 |
| 单卡待机功率 | 路径 B 无法扣空载 → **降级到路径 C 并标注** |
| PUE | 只能出 `energy_boundary=it_only` 版本，**须标注** |
| 分时碳强度 | 用近似推算，**须标注近似** |
| 设备隐含碳 | 出 `include_embodied=否` 版本，**须标注** |
| 训练总碳或预期服务量 | **只能出 Boundary B，不能出 C** |

## 十一、四个最容易犯的错

| # | 错误 | 后果 | 怎么防 |
|---|---|---|---|
| 1 | **先汇总能耗再乘平均碳强度** | 结果系统性偏差，且**看不出来** | 强制在 (m,k,t) 粒度算碳后再汇总 |
| 2 | **把空载能耗摊给模型** | 空置多的机型上，模型碳足迹被虚高 | 路径 B 第一步先扣空载 |
| 3 | **自训模型的训练碳算两遍** | 碳足迹虚高，且越是自训模型越严重 | 用 `model_trained_internally` 区分，内部训练走跨期分摊 |
| 4 | **隐含碳 kg 与 g 未换算** | 差 1000 倍 | `core/` 单元测试强制覆盖 |

> 建议在 `tests/test_carbon.py` 里**为这四条各写一个用例**，尤其是第 1 条——
> 构造一组「负荷与碳强度正相关」的数据，验证分时段算与先汇总算的结果确实不同。
