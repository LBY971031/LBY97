# 记忆档案 32：单位 token 能耗与生命周期分电源发电量的三段总结

对应表 N（单台部署各电源累计发电量）与表 M（三情景单位 token 能耗）。
等权场景（文本 50% : 代码 50%），单台部署，五年生命周期（30 660 运行小时）。

---

## 第一段　从服务器与运行模型的角度

四组平台–模型配置的单位 token 全站用电量介于 0.652~1.026 kW·h·(10⁶ token)⁻¹，最高值为最低值的 1.574 倍。该指标由单位 token 能耗与吞吐率共同决定，二者分别对应分子与分母：H200–Qwen3.5-397B 配置的加权单位 token 能耗为 1.625 J·token⁻¹（四者最高），加权吞吐率为 1 649 tok·s⁻¹，故全站用电量达 1.026 kW·h·(10⁶ token)⁻¹；A100–MiniMax-M2.7 配置的对应值分别为 0.855 J·token⁻¹ 与 1 786 tok·s⁻¹，全站用电量降至 0.652 kW·h·(10⁶ token)⁻¹。逐级拆解显示，GPU 侧用电量仅占整机 IT 侧的 41.8%~63.3%，其余由非 GPU 部件（1.9~2.6 kW）与 PSU 转换损耗贡献；整机 IT 侧至全站的增量固定为 15%，由 PUE = 1.15 决定，对应 0.085~0.134 kW·h·(10⁶ token)⁻¹。

GPU 侧至整机 IT 侧的放大倍数在四组配置间为 1.58~2.39 倍，且与 GPU 功率呈反向关系：A100–MiniMax-M2.7 配置的 GPU 功率为 1.53 kW，放大倍数达 2.39 倍；B200–DeepSeek-V4 配置的 GPU 功率为 5.39 kW，放大倍数降至 1.58 倍。其机理在于非 GPU 部件功率在各平台间仅相差 1.37 倍（1.9~2.6 kW），而 GPU 功率相差 3.52 倍，故 GPU 功率越低的配置，固定的非 GPU 开销所占比重越大。这一关系提示，以 GPU 能耗作为系统能耗的代理指标时，低功率配置的低估幅度最大。

五年累计口径下的排序与单位 token 口径不一致。B200–DeepSeek-V4 配置的五年负载侧用电量为 29.96 万 kW·h，为 A100–MiniMax-M2.7 配置（12.85 万 kW·h）的 2.332 倍，是四组中绝对用电量最高者；但其五年 token 产出为 4.11×10¹¹，达后者（1.97×10¹¹）的 2.087 倍，故单位 token 用电量仅为后者的 1.117 倍，在四组中位列第二低。**绝对用电量正比于整机功率，单位 token 用电量正比于功率与吞吐率之比**，二者的排序因而可以不同。引用能耗数据时须明确口径。

---

## 第二段　从电力接入情景的角度

三种电力接入情景下的单位 token 全站用电量完全相同（0.652~1.026 kW·h·(10⁶ token)⁻¹），差异体现在电源结构与电源侧电量需求上。在现状电网情景（S0）下，五年累计发电量等于负载侧用电量（12.85~29.96 万 kW·h），其中燃煤火电占 69.0%（8.87~20.67 万 kW·h）、风电占 22.0%、光伏占 9.0%。在绿电直连 + CCS 火力补电情景（S2）下，发电量合计同样等于负载侧用电量，由风电 40.8%、光伏 27.2% 与 CCS 火电 32.0%（4.11~9.59 万 kW·h）构成，燃煤火电的份额由 69.0% 降至 32.0% 且全部配置捕集设施。

绿电直连 + 储能补电情景（S1）是三者中唯一发电量高于负载用电量的情景。由于储能系统往返效率为 0.90，为向负载交付 32% 的补电电量，需从风光电源侧取用 35.56% 的电量用于充电，故发电量合计为负载用电量的 103.56%，四组配置对应 13.31~31.02 万 kW·h。储能环节的电量链路为：充电量 4.57~10.65 万 kW·h（占发电量的 34.3%），放电量 4.11~9.59 万 kW·h（占负载用电量的 32.0%），两者之差即往返损耗 0.46~1.07 万 kW·h（占负载用电量的 3.58%）。其余 8.74~20.37 万 kW·h 由绿电直供，不经储能环节。电量平衡关系为：发电量合计 = 绿电直供量 + 储能充电量，负载侧用电量 = 绿电直供量 + 储能放电量。

上述结果表明，储能方案的代价在负载侧计量中不可见，仅在电源侧显现。若按负载侧用电量确定风光装机规模，将出现 3.56% 的电量缺口；风光装机容量的确定须使用超配后的发电量合计。

## 第三段　讨论

综合前两段的结果，可以识别出一种近似的正交结构：**平台–模型配置决定用电量的大小，电力接入方案决定电量的来源构成，二者互不干涉。** 单位 token 用电量在三情景间保持不变，说明该指标仅对配置敏感；而各电源的发电量占比在四组配置间完全相同（S0 恒为 69.0%/22.0%/9.0%，S1 恒为 103.56% 的绿电需求，S2 恒为 68%/32%），说明电源结构仅对情景敏感。这一正交性在工程上具有实用含义：能效优化与电源结构优化可以分别推进，一方的改进不会削弱另一方的收益。以 S1 为例，若将平台–模型配置由 H200–Qwen3.5-397B 更换为 A100–MiniMax-M2.7，负载用电量下降 31.2%，储能配置规模、风光装机容量与超配电量按同一比例等比缩减。

但该正交性并不延伸至碳足迹与成本。隐含碳由整机质量与寿命内 token 产出决定，不随电源结构变化；折旧与运维按购置价计提，同样与电力方案无关。因此当运行侧被绿电大幅削减后，两个原本次要的分项会在占比上升至主导地位——在 S1 情景下，隐含碳占总碳的 34.3%~51.3%，购置阶段成本占总成本的 83.4%~84.1%。**能耗维度上成立的正交性，在碳与成本维度上被这两个不随情景变化的固定项打破。** 这提示评价体系不应止步于单位 token 能耗：该指标虽然物理意义清晰且对配置敏感，但它无法反映制造环节与资本投入，而这两项恰是绿电情景下的主导因素。

本节结果受三项边界设定制约，须在引用时一并说明。其一，计量边界为数据中心电表，未计入公共电网线损（蒙西电网综合线损率约 5%~6%）与绿电专线线损（约 1%~2%）的差异，该修正将扩大 S0 与绿电方案在电源侧电量需求上的差距。其二，非 GPU 部件功率取 1.9~2.6 kW，系按部件构成估算，尚待 PDU 实测校准；该参数直接决定 GPU 侧至整机侧 1.58~2.39 倍的放大关系。其三，吞吐率中 MiMo-V2-Flash 与 Qwen3.5-397B 两项由 PPT 报告的功率分布反推获得，不构成独立观测，其不确定度约为 2.4 倍，并按反比关系传导至单位 token 用电量。
