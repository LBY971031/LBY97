# 记忆档案 32：单位 token 能耗与生命周期分电源发电量的三段总结（精简版）

对应表 N（单台部署各电源累计发电量）与表 M（三情景单位 token 能耗）。
等权场景（文本 50% : 代码 50%），单台部署，五年生命周期（30 660 运行小时）。每节各一段。

---

## 第一段　从服务器与运行模型的角度

四组平台–模型配置的单位 token 全站用电量介于 0.652~1.026 kW·h·(10⁶ token)⁻¹，最高值为最低值的 1.574 倍，该指标由单位 token 能耗与吞吐率之比决定。逐级拆解显示，GPU 侧仅占整机 IT 侧的 41.8%~63.3%，放大倍数 1.58~2.39 倍并与 GPU 功率呈反向关系——非 GPU 功率在各平台间仅相差 1.37 倍而 GPU 功率相差 3.52 倍，故低功率配置承担的固定开销比重更大，以 GPU 能耗代理系统能耗时对其低估最为严重；整机至全站的增量固定为 15%。需注意两种口径的排序并不一致：B200–DeepSeek-V4 配置的五年累计用电量为 A100–MiniMax-M2.7 配置的 2.332 倍，为四组最高，但其 token 产出达 2.087 倍，单位 token 用电量因而仅为后者的 1.117 倍并位列第二低。绝对用电量正比于整机功率，单位用电量正比于功率与吞吐率之比，引用时须明确口径。

---

## 第二段　从电力接入情景的角度

三种情景下的单位 token 全站用电量完全相同，差异仅体现在电源结构与电源侧电量需求上。现状电网（S0）与绿电直连 + CCS 火力补电（S2）的五年累计发电量均等于负载侧用电量（12.85~29.96 万 kW·h），前者由燃煤火电 69.0%、风电 22.0%、光伏 9.0% 构成，后者由风电 40.8%、光伏 27.2%、CCS 火电 32.0% 构成。绿电直连 + 储能补电（S1）是唯一发电量高于负载用电量的情景：储能往返效率为 0.90，为交付 32% 的补电电量需自电源侧取用 35.56% 充电，发电量合计达负载用电量的 103.56%（13.31~31.02 万 kW·h），往返损耗 0.46~1.07 万 kW·h，占负载用电量的 3.58%。该电量代价在负载侧计量中不可见而仅在电源侧显现，风光装机容量的确定须使用超配后的发电量合计，否则将出现 3.56% 的缺口。

---

## 第三段　讨论

上述结果呈现一种近似的正交结构：平台–模型配置决定用电量的大小，电力接入方案决定电量的来源构成，二者互不干涉——单位 token 用电量在三情景间不变，各电源的发电量占比在四组配置间相同。其工程含义是能效优化与电源结构优化可分别推进而不相互削弱。然而该正交性并不延伸至碳足迹与成本：隐含碳由整机质量与寿命内 token 产出决定，折旧与运维按购置价计提，二者均不随电源结构变化，故当运行侧被绿电大幅削减后，这两个原本次要的分项升至主导地位——S1 情景下隐含碳占总碳的 34.3%~51.3%，购置阶段成本占总成本的 83.4%~84.1%。能耗维度上成立的正交性，在碳与成本维度被这两个固定项打破，提示评价体系不应止步于单位 token 能耗：该指标虽物理意义清晰，却无法反映制造环节与资本投入，而二者恰是绿电情景下的主导因素。上述结论受三项边界制约：计量边界为数据中心电表，未计入电网线损与专线线损的差异；非 GPU 部件功率为部件构成估算值，尚待 PDU 实测校准；MiMo-V2-Flash 与 Qwen3.5-397B 的吞吐率由功率分布反推获得，不构成独立观测。
