# 快速开始

给拿到这份代码的人：从零到跑出一份能碳报告。

---

## 一、不需要密钥就能跑的部分

先确认环境没问题。这一步**不花钱、不需要任何密钥**：

```bash
git clone https://github.com/LBY971031/LBY97.git
cd LBY97
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python demo/run_hour.py
```

会打印出**将要发送给模型的完整内容**——三段 JSON，里面每一个数字都是本机代码算出来的。

<span style="color:#888">（这是本项目的核心设计：数字由代码算，模型只负责把它们写成一段话。所以不接模型也能看到全部结果，只是没有那段文字叙述。）</span>

---

## 二、要用 Agent 的话，需要你自己的密钥

**本仓库不含任何 API 密钥，也不应该含。** 每个使用者用自己的：

### 1. 申请

到 https://console.anthropic.com/settings/keys 生成一把，形如 `sk-ant-...`。

<span style="color:#888">（用量记在你自己的账号上。本项目单次调用约 $0.05–0.2，具体见 [LLM 部署指南](./LLM部署指南.md) 的成本一节。）</span>

### 2. 填进 `.env`

```bash
cp .env.example .env               # Windows: copy .env.example .env
```

用记事本打开 `.env`，把 `sk-ant-在这里粘贴你的key` 换成你自己的。

**`.env` 已在 `.gitignore` 里，不会被提交。** 填一次即可，不用每次设环境变量。

### 3. 跑

```bash
# 调用其中一个 SubAgent
python demo/run_one_agent.py 1     # 任务与能耗
python demo/run_one_agent.py 2     # 绿电与低碳
python demo/run_one_agent.py 3     # 因子与核算

# 或者走完整流程
python demo/run_hour.py
```

## 二·五、换用 DeepSeek（可选）

不想用 Claude 的话，可以换成 DeepSeek，**代码一行都不用改**，只改 `.env`。

### 三步

```bash
pip install -r requirements-langchain.txt     # 这里面含 langchain-deepseek
```

在 `.env` 里填两行（模板 `.env.example` 末尾已经准备好，去掉注释号即可）：

```
DEEPSEEK_API_KEY=sk-你自己的key
LC_MODEL=deepseek-chat
```

密钥在 https://platform.deepseek.com/api_keys 生成。然后：

```bash
python check_setup.py                   # 会自动改查 DEEPSEEK_API_KEY
python demo/run_one_agent_lc.py 3       # 注意是 _lc 结尾那个
```

### 只有 LangChain 入口能用 DeepSeek

| 入口 | Claude | DeepSeek |
|---|---|---|
| `demo/run_one_agent.py` | 可用 | **不可用** |
| `demo/run_one_agent_lc.py` | 可用 | 可用 |
| `demo/run_hour.py` | 可用 | 第一段（确定性计算）可用，Agent 段不可用 |

<span style="color:#888">（原因：不带 `_lc` 的那条路走的是 Anthropic 官方 SDK 的 `tool_runner`，
那是 Anthropic 专有接口，指不到 DeepSeek 上。带 `_lc` 的走 LangChain，换 provider 只是换个字符串。）</span>

### 换模型之后，闸三可能更常报警

三道闸里，闸一、闸二是纯代码，跟用哪个模型无关。**闸三校验的是模型写出来的文字**——
不同模型遵守「不得自行做算术」这条指令的程度不一样。DeepSeek 如果更爱自己换算百分比、
自己求和，`verified=False` 就会更常出现。

这不是代码坏了，正是闸三该有的反应。建议：**先用 Claude 跑通一次当基线，再换 DeepSeek 对比**，
这样才分得清是模型行为差异还是代码问题。

## 三、密钥不要提交进仓库

这不是形式主义，是三个具体后果：

| | 后果 |
|---|---|
| GitHub 密钥扫描 | 检测到 Anthropic 密钥后通常几分钟内被自动作废，别人拿到也是废的 |
| 公开仓库被爬虫扫描 | 分钟级 |
| 用量记在密钥主人账上 | 别人花你的钱，且无法区分是谁在用 |

已经误提交过的，**删掉文件不够**——Git 历史里仍然查得到，必须去控制台作废重发。

## 四、目录里有什么

| 目录 | 内容 |
|---|---|
| `agent/` | 调用模型的那一层：三道闸、三个 SubAgent、编排器、提示词 |
| `core/` | 确定性算法。**所有数字在这里算出来**，不调模型 |
| `demo/` | 两个入口脚本 |
| `samples/` | 一小时的合成测试数据（10 个任务、4 台服务器） |
| `docs/` | 设计文档 |
| `能碳.md` | 完整项目文档 |

<span style="color:#888">（`samples/` 里的数据是**为测试编造的**，不是任何真实设施的实测值，不可用于报告或论文。里面刻意埋了一段数据缺口，用来验证系统在缺数据时会如实说「无法计算」而不是编一个数。）</span>

## 五、常见问题

**跑 `demo/run_hour.py` 说 `ANTHROPIC_API_KEY 未设置`**
正常。第一段（确定性计算）已经跑完并打印了，只是不接模型。按上面第二节填 `.env` 即可。

**`ModuleNotFoundError: No module named 'anthropic'`**
虚拟环境没激活，或没跑 `pip install -r requirements.txt`。

**`密钥无效`**
`.env` 里的 key 拼错或已作废，到控制台重新生成。

**报告里有些数字显示「无法计算」**
这是**正确行为**，不是故障。样本数据里 srv-03 在 15:20–15:35 缺少功率采样，
系统拒绝把缺失当 0 参与求和，所以全站合计返回空值而不是一个偏小的数。
